# Final Reflection
Throughout this course, I gained a much deeper understanding of how real-time embedded systems are designed and implemented. Before taking this class, my primary focus when writing software was simply producing the correct output. This course changed the way I approach embedded programming by emphasizing timing, scheduling, synchronization, and overall system architecture. I learned that in real-time systems, producing the correct answer is only part of the problem—the answer must also be produced within a predictable and guaranteed amount of time.

For my capstone project, I developed a dual-core FreeRTOS avionics monitoring and fault-tolerant telemetry system that demonstrated queues, event groups, direct task notifications, heartbeat monitoring, and worst-case execution time analysis. Integrating these concepts into one complete system was significantly more challenging than implementing each feature individually. Designing communication between multiple tasks while maintaining the proper behavior required careful planning and extensive debugging. Measuring worst-case execution time also proved more difficult than expected because debugging output and task scheduling influenced the measured execution times. Working through these challenges helped me better appreciate how timing analysis is performed in real embedded software projects.
